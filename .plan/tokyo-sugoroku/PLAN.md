# Tokyo Sugoroku - 東京観光スゴロク

## 概要・目的

キャンペーンサイトで利用可能な、東京の観光名所を巡るスゴロクゲーム。
1人プレイでサイコロを振り、マスに止まると観光スポットの情報がカード風に表示される。
クイズやミニゲーム等のリッチイベントを搭載し、ゴール後も何度でもループ周回できる。

## 技術スタック

| 技術 | 理由 |
|---|---|
| HTML + CSS変数 | フルスクリーンゲームUI。Tailwindは不要（カスタムデザイン主体） |
| Vanilla JS (ES2020+, type="module") | ゲームロジック・アニメーション・状態管理 |
| SVG (インラインSVG) | マップ描画・ルート線・スポットノード |
| CSS Animations + requestAnimationFrame | サイコロ演出・コマ移動アニメーション |
| Google Fonts (Noto Sans JP等) | 日本語フォント |

**SVG採用の理由:** 東京マップ風のボードはインラインSVGで描画。スポット間のルート線、コマのパスアニメーション（SVG `<animateMotion>`）に最適。イベントカード等のUI要素はDOM+CSSで実装。

## ゲームデザイン

### ボード構成

- **マス数:** 20マス（周回型・ループ）
- **レイアウト:** 東京マップ風（実際の地理的位置関係を反映）
- **各マスに東京の観光名所を配置**
- スポット間をルート線（SVG path）で接続
- 各スポットはドットノード + ラベルで表示
- コマがルート線に沿ってアニメーション移動

- 観光カード: 2マス（4, 6）

- 特殊: 2マス（1:スタート, 20:ゴール→ループ）

**巡回ルート概要:**
```

→ 浅草(6) → スカイツリー(7) → 両国(8) → 豊洲(9) → お台場(10)
→ レインボーブリッジ(11) → 上野(12) → 池袋(13) → 新宿(14)
→ 明治神宮(15) → 原宿(16) → 渋谷(17) → 中目黒(18)
→ 六本木(19) → 皇居(20) → [ループ: 東京タワー(1)へ]
```

### イベントタイプ

1. **観光カード**: スポットの説明・豆知識をカード風に表示（CSSグラデーション背景 + 絵文字アイコン）
2. **グルメカード**: ご当地グルメの紹介（食べ物の絵文字 + 説明）
3. **クイズ**: 東京に関する3択クイズ。正解で+10pt、不正解でそのまま
4. **ポイント追加**: +10pt〜+25ptを獲得（コイン獲得演出）
5. **進む/戻る/休み**: 古典的スゴロクイベント

**ミニゲーム（目押し・神経衰弱）はPhase 4（オプション）に格下げ。** MVP完成後に追加を検討。

### イベントルール

- **ボーナス移動（+Nマス/-Nマス）で到達したマスではイベントは発火しない**
- 「1回休み」は状態フラグ `skipNextTurn` で管理。ターン開始時にチェック＆リセット
- 「1回休み」でもサイコロコスト（5pt）は消費しない（スキップされるだけ）

### ポイントシステム

#### 基本設計

| 項目 | 値 |
|---|---|
| 初期ポイント | 50pt |
| サイコロ1回のコスト | 5pt |
| デイリーボーナス | 50pt（1日1回） |
| ポイント上限 | なし（無制限に蓄積可能） |

#### ポイント獲得手段

| 手段 | 獲得量 |
|---|---|
| デイリーボーナス（1日1回） | +50pt |
| ポイント追加マス | +10pt〜+25pt（マスにより異なる） |
| クイズ正解 | +10pt |
| 周回クリアボーナス | +30pt |

#### ポイント消費

- **サイコロを振る際に5pt消費**
- ポイントが5pt未満の場合、サイコロを振れない（ボタン無効化 + 「ポイント不足」表示）
- 「明日また来てね！」のメッセージで再訪を促す

#### デイリーボーナス仕様

- localStorageに最終ログイン日（`YYYY-MM-DD`形式）を保存
- アクセス時に日付比較 → 異なれば+50ptを付与 + 日付更新
- ボーナス獲得時にお祝い演出（コイン降ってくる等）
- 日付判定は**端末のローカル時間**基準（サーバー不要）

#### データ永続化（localStorage）

保存するキーと値:

```json
{
  "sugoroku_state": {
    "points": 50,
    "position": 1,
    "lap": 1,
    "skipNextTurn": false,
    "lastLoginDate": "2026-02-23"
  }
}
```

- ページリロード・ブラウザ再起動でも状態を復元
- 「リセット」ボタンで初期状態に戻せる（確認ダイアログ付き）

### サイコロ

- タップ/クリックで振る（**5pt消費**）
- ポイント不足時はボタン無効化
- 1〜6の目（CSS 3Dアニメーションで回転演出）
- 出目表示後、コマが1マスずつアニメーションで移動

### 周回（ループ）

- マス20到達（または超え）で周回カウント+1、**+30ptボーナス**
- `(currentPosition + diceValue - 1) % 20 + 1` で次のマスを算出
- コマは20→1→2…と1マスずつ順にアニメーション移動
- 周回クリア時に演出表示
- 周回カウンター表示（「2周目」等）

## UI/UXデザイン

### ターゲット端末

- **スマートフォン特化**（375px〜430px幅を主対象）
- 縦画面固定、`100dvh` でビューポート全体を使い切る
- **PC表示: スマホフレーム風のモックアップ内に表示**
  - `max-width: 430px` + `max-height: 932px`（iPhone 15 Pro Max相当）で中央配置
  - 周囲はダーク背景、コンテンツ部分にスマホ風の角丸フレーム
  - マウス操作でもタッチと同等に動作（ドラッグでパン、クリックでタップ）

### カラースキーム

- ベース: ダーク（`#0f0f1a`）
- アクセント: 桜ピンク（`#f472b6`）+ 金（`#fbbf24`）
- マス: イベントタイプごとに色分け（観光=青、グルメ=オレンジ、クイズ=緑、ポイント=金、移動系=紫）
- 和風モダンなテイスト

### レイアウト（スマホ縦画面・100dvh固定）

### マップの操作

- マップ領域は `overflow: auto` でタッチスクロール（パン）
- ズームは不要（SVGをマップ領域にフィットするサイズで描画）
- コマ移動時は `scrollIntoView({ behavior: 'smooth' })` で現在地にオートスクロール
- マップSVGはビューポート幅の約2倍のサイズ（横にも縦にもスクロール可能）

### タッチ操作

- サイコロボタン: 大きめのタップ領域（min-height: 56px）
- カード閉じる: タップ or 下スワイプ
- マップ: タッチスクロールのみ（ピンチズームなし＝実装シンプル）

### カード表示（ボトムシート風）

## 実装フェーズ

### Phase 1: 基盤（マップ + サイコロ + ポイントシステム）

- CSSベースのスクロール操作（overflow: auto）
- サイコロUI + 振るアニメーション（5pt消費）
- コマの移動アニメーション（1マスずつ）
- ポイントシステム（初期50pt、消費、獲得、表示）
- localStorage永続化（ポイント・位置・周回数・最終ログイン日）

- ポイント不足時のサイコロ無効化 + メッセージ

- 観光カード表示（モーダル風オーバーレイ）

### Phase 3: 演出・ポリッシュ

## 画像について

- **外部画像サービスに依存しない**（Unsplash直リンク等は使わない）
- 各スポットのビジュアル: CSSグラデーション背景 + 絵文字アイコンで表現
- サイコロ・コマ: CSS/SVGで描画（画像ファイル不要）
- 全てコードで完結し、外部リソース消失によるUI破損リスクをゼロにする

## 懸念点と対策

| 懸念 | 対策 |
|---|---|
| マップがモバイルで見づらい | CSSスクロール + 現在地オートスクロール |
| PC表示時の違和感 | max-width: 430pxのスマホフレーム内に固定。PCでもスマホ操作感を再現 |
| ルート線の交差 | 地理的巡回順に並べ替え済み。環状ルートで交差を最小化 |
| ゲーム状態の複雑さ | 状態オブジェクトを一元管理、不変更新パターン |
| スコープ肥大化 | ミニゲームをPhase 4に格下げ。Phase 1-3でMVP完成 |
| イベント連鎖バグ | ボーナス移動先ではイベント非発火のルールを明確化 |
| ポイント経済の破綻 | 1周20マスで獲得可能pt（ポイントマス計85pt+クイズ40pt+周回30pt=155pt）に対し消費は最低20回×5pt=100pt。黒字設計で持続可能 |
| localStorage消去 | ブラウザのデータクリアで進行がリセットされる。キャンペーンサイトとしては許容範囲 |
| 日付操作チート | 端末時刻を変更すればデイリーボーナス乱用可。サーバーレスなので防止不可→許容 |

## ファイル構成（予定）

```
tokyo-sugoroku/
├── index.html
├── meta.json
└── assets/
    ├── css/
    │   └── sugoroku.css
    └── js/
        ├── main.js          ← エントリーポイント・初期化・ゲームループ
        └── data.js          ← 観光名所データ・クイズデータ・マップ座標
```

**2ファイル構成の理由:** データ（20スポット・クイズ等）はボリュームが大きいため分離。ロジックは `main.js` に集約し、800行以内を目標。超えた場合に初めて分割を検討する。
